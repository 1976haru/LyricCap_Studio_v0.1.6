# LyricCap Studio v0.1.5

JSON/TXT의 정확한 가사 + WAV/MP3 음원을 넣으면 **실제 음원을 분석해 가사 타이밍을 잡고**, 영어/한국어/일본어 SRT를 만들어 CapCut에 바로 가져오는 Windows 데스크톱 앱입니다.

## v0.1.5에서 가장 중요한 수정

이전 버전에는 stable-ts가 원래 가사 줄 구조를 그대로 돌려주지 못했을 때, 전체 타임라인에 가사 줄을 비례 분배하는 안전장치가 있었습니다. 이 방식은 파일은 만들어지지만 노래와 싱크가 크게 틀어질 수 있어 **완전히 제거했습니다.**

v0.1.5는 기본값으로 다음 순서를 사용합니다.

1. WAV/MP3 실제 음원 읽기
2. **Demucs로 보컬 분리**
3. **Silero VAD로 실제 보컬/무보컬 구간 검출**
4. stable-ts forced alignment로 JSON/TXT의 정확한 가사를 실제 보컬 위치에 정렬
5. 각 가사 줄의 실제 첫 단어~마지막 단어 타임스탬프로 SRT 생성
6. 정렬이 실패하면 **가짜 타임코드를 만들지 않고 오류로 중단**

stable-ts가 줄 구분을 변경해도 전체 곡 길이에 비례 배분하지 않습니다. 실제로 정렬된 word timestamp를 다시 가사 줄에 묶습니다.

## 싱크 방식

### 정밀 음악 싱크 (보컬 분리 + VAD, 권장)
플레이리스트/Suno 노래에 권장합니다.

- Demucs 보컬 분리
- VAD 사용
- 실제 음원 기반 forced alignment
- 첫 실행 시 Demucs 모델 다운로드 때문에 시간이 더 걸릴 수 있음
- CPU에서는 15~20곡 처리 시간이 꽤 길 수 있음

### 빠른 음악 싱크 (VAD, 보컬분리 없음)
반주가 단순하고 보컬이 매우 선명할 때 사용할 수 있습니다.

### 음성/내레이션 싱크
노래가 아닌 일반 음성용입니다.

### 타임스탬프 정밀 보정(느림)
기본 싱크 후 한 번 더 timestamp refinement를 수행합니다. 먼저 끈 상태로 1곡을 테스트하고, 시작/끝이 수백 ms 정도 아쉬울 때 켜는 것을 권장합니다.

## 정렬 모델 추천

영어 Suno 노래 기준:

- `base.en`: 빠른 테스트
- `small.en`: **정확도 우선 권장**
- `medium.en`: 더 무겁고 느림

한국어/일본어 원문은 `.en`이 없는 `base`, `small`, `medium`을 사용하세요.

## 지원 출력

- 영어 (`en`)
- 영어 + 한국어 (`en_ko`)
- 영어 + 일본어 (`en_ja`)
- 한국어 (`ko`)
- 일본어 (`ja`)
- 곡별 SRT
- 전체 플레이리스트 통합 SRT

## 자연번역

JSON/TXT에 영어 가사만 있어도 한국어/일본어 자막을 만들 수 있습니다.

### AI 자연번역 (Gemini, 권장)
- 인터넷 연결 + Gemini API 키 필요
- 한 줄씩 따로 직역하지 않고 **곡 전체 문맥**을 보고 번역
- 후렴/훅, 대명사, 호칭, 감정을 일관되게 유지
- 입력 1줄 ↔ 번역 1줄을 검증해 SRT 타이밍을 유지

### 오프라인 빠른번역 (Argos)
- 최초 언어 모델 설치 후 오프라인 사용 가능
- 비용 없음
- 직역투가 생길 수 있음

## 입력 JSON 예

```json
{
  "meta": {"songCount": 15, "lyricLanguage": "english"},
  "songs": [
    {"trackNo": 1, "title": "...", "lyrics": "[verse]\n..."}
  ]
}
```

`[Verse]`, `[Chorus]`, `[instrumental break]` 같은 대괄호 태그는 자막에서 자동 제외합니다.

## 처음 설치

`START_HERE.bat`을 더블클릭합니다.

- Python 3.11/3.12 자동 확인/설치 시도
- FFmpeg 확인/설치 시도
- 전용 `.venv` 생성
- stable-ts / **Demucs** / Argos / mutagen 설치
- 오류 시 `setup_log.txt` 기록

설치가 끝난 뒤에는 `RUN_LYRICCAP.bat`만 실행하면 됩니다.

## 권장 첫 테스트

처음부터 15~20곡을 돌리지 말고 **JSON 한 곡 + 해당 WAV/MP3 한 곡**으로 먼저 확인하세요.

1. `가사 JSON/TXT` 선택
2. WAV/MP3 1곡 선택
3. `정밀 음악 싱크 (보컬 분리 + VAD, 권장)` 유지
4. 영어 원문이면 `small.en` 권장 (`base.en`으로 먼저 빠른 테스트도 가능)
5. 우선 `영어`만 체크
6. `▶ 자막 전체 생성`
7. 곡별 SRT를 CapCut에 넣어 실제 보컬과 맞는지 확인
8. 만족하면 15곡 전체 + 영한/영일 번역을 생성

## 출력 구조

```text
output/
  tracks/
    01_Title_en.srt
    01_Title_en_ko.srt
    01_Title_en_ja.srt
    01_Title_ko.srt
    01_Title_ja.srt
  combined/
    PLAYLIST_en.srt
    PLAYLIST_en_ko.srt
    PLAYLIST_en_ja.srt
    PLAYLIST_ko.srt
    PLAYLIST_ja.srt
```

## CapCut 통합 SRT의 전제

통합 SRT는 **각 원본 음원 길이를 순서대로 합산**해서 다음 곡 시작점을 계산합니다.

따라서 CapCut에서도:

- 같은 음원 파일
- 같은 순서
- 속도 변경 없음
- 앞/뒤 잘라내기 없음
- 곡 사이 간격이 프로그램 설정과 동일

이어야 통합 SRT가 계속 맞습니다.

예를 들어 CapCut에서 모든 곡 사이에 0.5초 빈 공간을 넣었다면 프로그램의 `곡 사이 간격(초)`도 `0.5`로 지정해야 합니다. 크로스페이드 때문에 두 곡이 겹치면 단순 간격 방식 통합 SRT와 차이가 생길 수 있습니다.

## 중요한 원칙

**v0.1.5는 실제 음원 정렬에 실패했을 때 SRT를 억지로 생성하지 않습니다.**

오류가 나면 해당 WAV/MP3 + JSON/TXT + `error.log`를 확인해 싱크 엔진을 조정하는 방식이 맞습니다. 파일은 만들어졌지만 노래와 전혀 안 맞는 상태보다 실패를 명확히 표시하는 것을 우선합니다.
